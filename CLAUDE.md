# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`surrealdb_live_message` is a **library-first** crate (`src/lib.rs`) demonstrating agent-to-agent
messaging over SurrealDB graph edges + LIVE queries, with `src/main.rs` as a binary example.

## Build & Test

- Integration tests require **Docker** — `sdb_server.rs` spins up a SurrealDB container via `bollard`.
- Run: `cargo test --test integration_test` (the Docker-backed integration test).
- Deterministic unit tests (no Docker) live in `src/subsystems/agents.rs` (the
  `await_ready` handshake-error seam): `cargo test --lib`.
- Against the production cloud endpoint instead of a local container: `RUN_MODE=production cargo test --test integration_test`.
- Config layers (via the `config` crate): `config/default.toml` → `config/{RUN_MODE}.toml` → env vars (`__` separator). `RUN_MODE` defaults to `development`.

## SurrealDB SDK gotchas (do not regress)

These were diagnosed fixes; tests lock them in. See docstrings in `src/message.rs` and `src/subsystems/agents.rs`.

1. **Edge fields need `#[surreal(rename = "in")]`.** `SurrealValue` derive uses raw Rust identifiers as wire keys, so `r#in` would serialize as `"r#in"`. SurrealDB emits `"in"` for edge source. **serde `rename` is ignored** — must use the `#[surreal(...)]` attribute. (`src/message.rs:34`)
2. **A bare `SELECT *` / `LIVE SELECT *` on edge records omits `in`/`out`.** Read edge pointers with an explicit projection — `SELECT *, in, out FROM message WHERE ...` (`tests/integration_test.rs:153`, `:177`, `:298`; the pointer assertions at `:167`–`:174` lock it in). The **durable bus sidesteps this**: `SHOW CHANGES` changeset records carry `id`/`in`/`out` natively, so the wake-up subscription is only `LIVE SELECT id FROM message WHERE out = $owner` (`src/subsystems/agents.rs:1448`). The gotcha still applies to any plain `SELECT` you add.
3. Payload types must derive `SurrealValue` — `Message<T: SurrealValue>`, not just `Serialize`.

## Lifecycle / shutdown contract

- `Coalition` owns a root `CancellationToken` (a child of the caller's token with `Coalition::new_with_parent`), spawns listen-loops on `child_token()`, and exposes `cancellation_token()` + `shutdown().await`. Dropping a `Coalition` cancels its root token without waiting; `shutdown().await` cancels it and waits for the listen loops and the retention sweep to end. The library installs no signal handling: callers wire top-level shutdown (e.g. bare `tokio::signal::ctrl_c`) outside the library. Don't add signal handling or `tokio-graceful-shutdown` inside the lib.
- **Delivery bus:** agent `listen_loop`s send each message their catch-up reads onto a shared **async-channel MPMC** channel as `Delivery<T> { recipient, message }`. Consume via `coalition.inbox()` (an `async_channel::Receiver`) — clone for multiple workers; sync handlers call `recv_blocking()` on a blocking thread. Bus is `async_channel::bounded(INBOX_CAPACITY=256)` (backpressure: `send` waits while full) and closes once all agents shut down: `recv()` returns the queued deliveries, then `Err(RecvError)`.
- `Coalition::new` performs a **readiness handshake**: it awaits every listen-loop's ready signal (bounded by `READY_TIMEOUT`, cancels the root token on failure) before returning, so the first `Agent::send` is guaranteed observed. Each listen-loop signals after its first LIVE subscribe and its first catch-up page query succeed; an error before then is logged with its source chain and sent on the ready channel (`oneshot::Sender<Result<()>>`), so `Coalition::new` returns that error. Each loop then holds at its ready point until `Coalition::new` has every ready signal and sends the start signal, so no delivery reaches the bus before `Coalition::new` returns `Ok`, and a failed `Coalition::new` moves no cursor past a message that was not on the bus (`scenario_failed_new_keeps_backlog`); a backlog larger than the bus does not block `Coalition::new` (`scenario_startup_backlog`). `Agent::new` writes `agent:<name>` and, when absent, `cursor:<name>` in one transaction (a new agent starts after the highest versionstamp in the whole `message` changefeed, read in pages until a page holds fewer than 1000 changesets, in a database where `message` is the one table with a changefeed (`scenario_new_agent_skips_a_long_feed`); a `Coalition::new` reads the feed at most once, for its first new agent (`scenario_new_agents_share_one_walk`); an existing agent without a cursor starts at versionstamp 0 with no feed read, with a warn log, so its retained backlog is delivered (`scenario_lost_cursor_replays_backlog`)), so `Agent::new` does not write an agent without its cursor; an existing cursor is kept (`scenario_failed_new_keeps_fresh_cursor`). A failed changefeed read in `Agent::new` returns `AgentCreate`, as does a page that is not an array, a full page with no integer versionstamp, and a page whose highest versionstamp is below its `SINCE` or is `i64::MAX`. The loop's cursor load is a pure load (a missing row is `CursorLoad`). Each database call of `Agent::new` in `build`, each changefeed page among them, is bounded by the ready timeout (`AgentCreateTimeout` for that agent; `scenario_stalled_agent_record_returns_create_timeout`) and raced against the token, so the whole `Agent::new` has no fixed bound. Every listen-loop await before the ready signal (connection, cursor load, LIVE subscribe, first page query) is raced against the loop's token, so a startup database call that never completes does not stop `Coalition::new` returning `ReadyTimeout` (`scenario_stalled_startup_returns_ready_timeout`). A token cancelled before every loop is ready returns `Error::Cancelled { agent }`: `None` when `build` finds it before any database call (`scenario_cancelled_parent_makes_no_db_call`) or after the readiness waits end in `Ok` or `ReadyTimeout` (`scenario_cancel_after_ready_before_start`); `Some(name)` when it interrupts that agent's `Agent::new` or loop startup (`scenario_cancel_during_first_page`). A loop sends `Cancelled` on its ready channel before any cleanup await. `ListenLoopDropped` means only that a loop ended without a ready signal and without a cancel. The readiness waits start after the last `Agent::new` call. The first sent error (including `Cancelled`) is returned as soon as those waits see it, in preference to `ReadyTimeout` and `ListenLoopDropped`; among those two, the one for the earliest name wins. A subscribe in flight at a cancel moves to a spawned task that no `TaskTracker` tracks, so neither the loop nor `shutdown()` waits for it, and the live count can settle after they return. That task ends the live query when the reply arrives, and logs a failed subscribe, a failed or timed-out `KILL` call, a reply still missing after `LIVE_KILL_TIMEOUT` (it then keeps waiting), and its own drop before it finishes, each at warn. The SDK drops the result of a `KILL` statement (`surrealdb-3.3.5/src/method/query.rs:429`). A repeated name fails with `DuplicateAgentName` before any database call or spawn. If `Coalition::new` fails after spawning, it cancels and waits for every spawned loop before it returns (`scenario_build_failure_teardown`). Dropping the `Coalition::new` future cancels every spawned loop and the retention sweep without waiting (a `DropGuard` on the root token, disarmed just before `Ok`; `scenario_dropped_new_cancels_loops`); a loop whose ready send fails ends. Preserve the ready-signal and start-signal paths.
- **Catch-up cursor:** `cursor:<agent>` holds `versionstamp` and `change_index` (default 0); a row that is not an object with non-negative integers fails with `CursorLoad`. Each bus send and each page query is raced against the agent's cancel token, and the LIVE wake stream is still read while a send waits. The cursor advances past a message addressed to the agent only once its delivery is on the bus; it is persisted after each page and on a stop, and the in-memory cursor moves only after the save succeeds. Malformed data is one rule: a changeset that is not an object or has no integer versionstamp (it has no position; the cursor passes it only by moving to a later changeset), a missing or non-array `changes`, a change that is not an object or whose op key is not `update`, `delete` or `define_table`, a record that is not an object, a record whose `out` is missing or not a record id, and a message whose payload does not decode as `T` are logged at error level and skipped (`delete` and `define_table` ops, and messages for other agents, are skipped without a log). A `SHOW CHANGES` reply that is not an array fails the catch-up with `CatchUp`. Each `update` op of a message record for the agent is one delivery, so a message record updated after creation is delivered again. For message records that are only created: after a stop whose save succeeds, no message is put on the bus twice; after a failed save or a process exit mid-page, the messages sent since the last saved position are put on the bus again. Deliveries already on the bus are not replayed: they are lost if the process exits, or every receiver is dropped, before a consumer reads them. `close()` on any receiver stops further sends, and the queued deliveries stay readable. Integration scenarios `scenario_startup_backlog`, `scenario_full_bus_shutdown_and_replay`, `scenario_stop_mid_changeset`, `scenario_cancel_during_first_page`, `scenario_drop_cancels`, `scenario_malformed_cursor`, and `scenario_wake_during_pass` lock this in.
- **Production top-level shutdown** lives in `examples/` (not `main.rs`, which is the minimal `ctrl_c` demo). Three requirements bare `ctrl_c` misses: handle **SIGTERM** (not just SIGINT), race startup readiness against sdb-task failure + a timeout (else `wait_until_ready` hangs), and bound the drain — **order: `coalition.shutdown()` first, then cancel the sdb token** (agents persist cursors and KILL the live queries of their subscribed streams while the DB is still up). This order does not cover the `KILL` of a subscribe in flight at the cancel. `examples/production_shutdown.rs` = hand-rolled (zero-dep, single subsystem); `examples/graceful_shutdown.rs` = `tokio-graceful-shutdown` (multi-subsystem supervision + failure propagation). A coalition built with `Coalition::new` has a token independent of the daemon root; call `coalition.shutdown()` to wait for its drain (dropping it only cancels).

## Conventions

- Library code returns a typed **`thiserror`** enum — `crate::error::Error` / `crate::error::Result`. `anyhow` is used **only** in `src/main.rs` and `tests/` (its `?` absorbs `Error` via the blanket `From`). No `unwrap()` in library code; `.expect()` only at fatal startup points (`settings::SETTINGS`, `sdb::client`, `sdb_task`) and as `.expect("invariant: …")` where a precondition makes the other branch unreachable and the message states it.
- Workflow: commit **direct to `main`** (no PR gate). Track TODOs in `TODO.md`.
